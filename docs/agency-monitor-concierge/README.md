# Agency Monitor — Concierge MVP 運用キット

「監視 → 異常検知 → 原因・insight → 推奨」までを、**新規開発ゼロ**（GA4 + Google Ads 管理画面 + スプレッドシート + メール + 既存 Viewtrace）で、
あなたが裏側で手動で回すための運用一式です。目的は **Agency Monitor が売れるかを検証すること**（＝最初の営業テスト）。

---

## 0. 何を検証するのか（これを見失わない）

- 代理店は「毎日全アカウントを確認する作業」を減らしたいと本当に思っているか？
- 「今日見るべき口座 / 原因 / 打ち手」を毎週届けると、価値を感じて **お金を払う意思** を示すか？
- どのアカウントに **Viewtrace の"実際に何が表示されたか"の記録** が効くか（＝独自価値の確認）。

> **提供範囲は ①監視 → ②異常検知 → ③原因・insight → ④推奨 まで（アドバイザリー）。**
> ⑤実際の広告操作は**やらない**（金銭・法的責任と技術ハードルを避けるため）。操作は代理店側が承認して行う。
> **お客様には常に"目安"として提示する**（成果保証ではない／最終判断は代理店）。レポート末尾に免責文を必ず入れる。

## 1. 前提コスト（重要）

| 項目 | コスト |
|---|---|
| GA4（レポート閲覧） | 無料 |
| Google Ads 管理画面（閲覧・CSVエクスポート） | 無料 |
| スプレッドシート / メール | 既存のもの |
| Viewtrace（観測・記録） | 既存プロダクト |
| **新規の月額支出** | **実質ゼロ円** |
| **本当のコスト** | **あなたの工数：1代理店(3〜5口座)で週3〜6時間** |

読み取り専用で進めるため、**広告費や配信設定には一切触れません**（＝金銭・法的リスクを負わない）。

---

## 2. 週次ループ（毎週この3ステップ）

```
月曜: 収集      → 各口座の直近7日 vs 前7日 vs 目標 を取得（GA4/Google Ads/ Viewtrace）
火曜: 分析      → analysis-checklist.md に沿って異常検知 → 原因仮説 → 推奨 を account-tracker.csv に記入
水曜: 配信      → weekly-report-template.md で「異常→原因→推奨」の3点セットを作り、delivery メールで送付
```

### 時間の目安（3〜5口座）
- 監視＋異常検知：口座あたり 10〜20分
- 原因分析＋insight：口座あたり 15〜30分（一番頭を使う）
- 推奨レポート作成：口座あたり 10〜15分
- → 合計 **週3〜6時間**

---

## 3. ファイル一覧と使い方

| ファイル | 役割 | いつ使う |
|---|---|---|
| `access-request.md` | 閲覧権限の依頼文＋キックオフメール（日英） | 開始時（1回） |
| `analysis-checklist.md` | 口座別チェック項目・異常検知の閾値・原因/推奨の型 | 毎週（火） |
| `account-tracker.csv` | 全口座の数値と判定を記録するスプレッドシート雛形 | 毎週（火） |
| `weekly-report-template.md` | 代理店に見せる週次レポート（異常→原因→推奨・日英） | 毎週（水） |

---

## 4. 進め方（最初の2週間）

1. `access-request.md` のキックオフメールで、1代理店に「3〜5口座・2週間・無料・読み取り専用」を提案。
2. 権限（GA4 Viewer / Google Ads 読み取り、または週次CSVエクスポート）をもらう。もらえない場合はCSVでも可。
3. 対象URLを **Viewtrace に登録**して観測を開始（LPの改ざん/崩れ/404/価格変化を"記録付き"で捉えるため）。
4. 週次ループを2回（＝2週間）回して、`weekly-report-template.md` で2通のレポートを届ける。
5. 反応（返信・電話・「続けたい？」への回答）で **有料化の意思** を判定。

### 成功のサイン
- 「これ毎週ほしい」「うちの他の口座もやって」「いくら？」が出たら勝ち。
- そこで初めて自動化・課金設計に進む。
